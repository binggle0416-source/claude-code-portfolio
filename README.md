## 프로젝트를 관통하는 작업 방식

1. **PRD/계획서 먼저, 질문받으며 결정** — 모든 프로젝트를 "바로 만들지 말고 나한테 물어보면서 PRD부터"로 시작했다. 선택지 질문으로 범위·스택·형식을 빠르게 확정할 수 있었다.
2. **마일스톤 단위 진행** — "M1 커밋하고 다음 단계" 식으로 쪼개면 중간 검토가 쉽고 되돌리기도 쉽다.
3. **파일럿 먼저** — 매뉴얼은 8장, 메일 작성기는 본문 생성 로직부터. 형식 합의 후 확장하면 재작업이 거의 없다.
4. **추측 금지, 근거 요구** — 기준·규정은 문서를 요청하거나 원문을 찾게 하고, 추정값엔 "(추정)"과 근거를 붙이게 했다.
5. **되돌릴 수 없는 동작은 사람이** — 로그인·확정·상신·발송은 사람이 하고, Claude는 조회·초안·임시저장까지.
6. **Claude가 스스로 검증** — 테스트 코드, 브라우저 클릭 테스트, 렌더링 이미지 검수까지 맡겨 결과를 보고받는다.
7. **반복되면 스킬로** — 한 건을 끝까지 처리한 뒤 "아무나 쓸 수 있게 스킬로 만들어줘"로 절차를 남긴다.

## 보안 원칙 (배운 점)

- 비밀번호·토큰은 채팅에 붙여넣지 말고 `.env.local` 등 로컬 파일이나 환경변수로 넘긴다.
- 원본 프로젝트 폴더(PRD, 샘플, DB, 스킬 예시 데이터)에는 실제 업무 데이터가 있으므로 이 저장소에는 **요약본만** 올린다.

## 새 프로젝트 추가하는 법

`projects/<이름>.md`를 같은 형식(요약 표 → 목표 → 클로드 활용 방식 → 결과물 → 잘된 점 → 아쉬운 점 → 재사용 프롬프트)으로 만들고 위 표에 한 줄 추가한다.
Claude Code에 "이 프로젝트도 정리본에 추가해줘, 회사 데이터는 빼고"라고 요청하면 된다.
