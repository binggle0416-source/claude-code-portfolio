# Strategy GATE 사용자 매뉴얼 자동 제작 (브라우저 캡처 → PPT → 제본 PDF → 스킬화)

> 크롬 확장으로 Claude가 로그인된 웹 시스템을 직접 돌아다니며 화면을 캡처하고, 번호 콜아웃이 붙은 73장짜리 PPT 매뉴얼과 제본용 PDF 3종을 만든 뒤 그 절차를 재사용 가능한 스킬로 묶은 프로젝트

| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-16 ~ 2026-11-12 (핵심 작업은 10-29 하루, 약 1.5시간) |
| 세션 수 | 4개 (접속 확인 1, 매뉴얼 제작 1, 신규 UI 소개서 1, 메일 첨부파일 수집 1) |
| 기술 스택/도구 | Claude Code + Claude in Chrome(크롬 확장), Node.js(pptxgenjs, pdf-lib), PowerShell(크롭·렌더·PDF 변환·몽타주), pptx·skill-creator 스킬 |
| 결과물 형태 | PRD(md), PPTX 매뉴얼(파일럿 → v1.0 → v1.1 → v1.2), 인쇄용 PDF 3종 + 인쇄 안내문, `.skill` 패키지 + 받는 사람용 사용안내, (부가) 신규 UI 기업 소개서 PPTX |
| 상태 | 완료 (v1.2 최종본, 스킬 배포용 패키징 완료 / 새 대화에서의 스킬 실사용 검증은 미완) |

## 목표 / 배경
- 사내 전략경영관리 솔루션 Strategy GATE의 현업 사용자(지표 담당자, 실적 입력자, 승인자, 평가자, 피평가자)용 매뉴얼이 필요했다.
- 범위는 조직성과·개인성과·경영평가 3개 모듈. 메뉴만 약 100개라 "현업이 실제로 쓰는 입력·승인·평가·조회 화면"만 추리고 관리자 설정 화면은 제외해야 했다.
- 사람이 화면을 하나씩 캡처하고 PPT에 붙이는 반복 작업을 Claude에게 맡기고, 다음 사람도 같은 방식으로 만들 수 있게 절차 자체를 남기는 것이 목표.

## 클로드 활용 방식
1. **PRD 먼저, 질문하면서 정하기**
   - 첫 지시: "어떻게 할지 나한테 물으면서 PRD 해주고 진행해보자".
   - Claude가 대상 시스템·모듈·데이터 기준 연도·산출물 형식을 질문 → 로그인 후 메뉴 구조를 JS로 추출 → "화면 약 100개라 범위를 좁혀야 한다"고 제안 → 대상/제외 화면 표(그룹·화면명·화면코드)까지 담은 PRD 작성.
   - PRD에 작업 원칙 명시: **조회만 수행**(저장·승인·삭제·제출 버튼 금지, 데모 데이터 보존), 세션 만료 시 재로그인 요청, 슬라이드 형식(화면 1장 + ①②③ 콜아웃 + 우측 설명 + Tip/주의).
2. **로그인은 사람이, 탐색·캡처는 Claude가**
   - Claude가 로그인 페이지만 열어두고 사용자가 직접 로그인 → "로그인 완료" 신호 후 작업 시작.
   - 화면 이동은 URL 해시(화면코드)로 직접 이동, 연도·월 조회조건은 `javascript_tool`로 select 값 변경 + change 이벤트 발생.
   - 데이터가 비는 화면은 조직을 '전체'로 바꾸거나 다른 평가대상자를 골라 데이터가 있는 조건을 스스로 찾음. 마감 전에만 보이는 버튼은 버튼 영역만 확대 캡처.
   - 캡처 직전 마우스를 화면 구석으로 hover해서 커서가 찍히지 않게 함. 스크린샷은 디스크 저장 후 `cap.sh`로 `화면코드_순번_설명.jpg` 이름을 붙여 모음(약 70컷).
3. **파일럿 → 전체 생성**
   - 화면 3개로 8장짜리 파일럿을 먼저 만들어 형식을 확인받고("이 형식으로 진행") 전체로 확장.
   - `build_manual.js`(약 1,500줄, pptxgenjs)에 `screenSlide`, `chapterSlide`, `note`, 상세 목차 자동 생성 helper를 두고, 콜아웃 좌표는 캡처 이미지 픽셀 기준으로 지정.
4. **렌더링 자가 검수**
   - PowerPoint로 슬라이드를 PNG로 뽑고 여러 장을 몽타주로 묶어 겹침·잘림·줄바꿈을 Claude가 눈으로 확인하고 수정한 뒤 보고.
5. **제본용 인쇄본**
   - "제본하기 편하게"라는 요청에 인쇄 방식을 질문한 뒤, pdf-lib로 슬라이드 PDF를 A4에 재배치: 제본 여백 20mm, 양면일 때 장 표지가 항상 오른쪽 면에 오도록 빈 면 삽입, 2-up 축소판.
6. **스킬화**
   - skill-creator로 `sgate-manual` 스킬 생성: SKILL.md(요구사항 질문 → PRD → 로그인 → 캡처 → PPT → 인쇄 절차), 캡처 실전 가이드, 메뉴 목록(현업/관리자/모니터링 구분), 관리자 매뉴얼용 참고, 빌드 템플릿과 보조 스크립트 일체.

| 버전 | 내용 |

| v1.0 | 3개 장 전체, 72장. 시작하기(로그인·화면 구성) + 장별 업무 흐름도 + 화면별 슬라이드 |
| v1.1 | 한쪽으로 쏠린 캡처 4장을 크롭·박스 맞춤 배치로 교정 (열린 파일 잠금 때문에 새 버전으로 저장) |
| v1.2 | 상세 목차를 한 장으로 정리(겹침·장 제목 분리 수정), 73장. 제본 PDF의 원본 |
| 인쇄용 | A4 가로 양면 왼쪽제본(78쪽) / A4 가로 단면 왼쪽제본(73쪽) / A4 세로 한 면 2장(37쪽) + 인쇄 안내문 |

- **빌드 구조**: `build/`(build_manual.js, make_print.js, crop·render·topdf·pdfpng·sheet·mont 등 PowerShell 스크립트, print_meta.json에 장 표지 쪽 번호 저장) / `captures/`(화면코드별 캡처) / `인쇄용/` / `skill/`.
- **스킬화**: 됨. `sgate-manual.skill` 패키지 + 받는 사람용 "설치 → 준비 → 요청 → 로그인 → 확인" 5단계 사용안내 별도 파일. 압축 시 경로 구분자를 슬래시로 맞춰 다른 환경에서도 풀리게 처리.
- **파생 작업**: 같은 방식으로 신규 UI 데모 화면 23개를 캡처해 기존 PDF 소개서 구성을 참고한 기업용 상세 소개서(37장)도 제작.

## (부가) 메일 첨부파일 찾기 작업
- 상황: 퇴사한 이전 담당자가 파일을 따로 남기지 않아, 그룹웨어(아마란스) 받은메일함에서 그 사람이 보낸 메일의 첨부파일을 모아야 했다.
- 방식: 보낸 사람 + 첨부 있음 조건으로 상세검색(약 200건) → 내부 API는 요청이 암호화돼 있어 포기 → 페이지에 JS 루프를 넣어 "메일 열기 → 첨부 전체 선택 → PC 저장"을 자동 클릭, 메일마다 다운로드 시각을 기록해 파일과 메일을 매칭.
- 정리: 메일별 폴더 생성 → 대용량 첨부 링크 별도 수집 → 다른 계정에서도 반복(수신일시 기준으로 이미 받은 메일은 건너뜀) → 고객사별 폴더로 재그룹 → 소개서만 보낸 메일 폴더 비우기. 중복 파일은 완전 삭제 대신 휴지통으로 이동.
- 걸림돌: 목록이 80건 단위로 멈춤(재시작 지점 지정), 탭이 뒤에 가려지면 속도 저하, CSV 수정 중 열 손실·빈 폴더 발생 → 원본 메일 목록으로 재생성해 복구.

## 잘된 점
- PRD + 파일럿을 먼저 거쳐 형식 합의 후 전체를 돌렸기 때문에, 72장 생성 후 수정은 캡처 4장과 목차 정도로 끝났다.
- "조회만" 원칙과 "로그인은 사용자가" 원칙을 PRD·스킬에 박아두어 운영 데이터 훼손 걱정 없이 맡길 수 있었다.
- Claude가 렌더링 이미지를 직접 보고 검수하는 루프 덕분에 레이아웃 오류가 사람 눈에 가기 전에 대부분 걸러졌다.
- 인쇄 방식을 모를 때 3종을 다 만들어 고객이 고르게 한 판단이 실용적이었다.
- 시행착오(조회조건 JS, 커스텀 드롭다운, 데이터 있는 조건 등)를 capture_guide로 남겨 다음 작업 시간이 줄어든다.

## 아쉬운 점 / 시행착오
- 일부 캡처가 한쪽으로 쏠려 있었는데 사용자가 먼저 발견함 → 이후 "쏠린 캡처 금지 + 크롭" 규칙을 스킬에 추가.
- 확장 브라우저 뷰포트가 고정(1568x652)이라 창 크기 변경이 안 먹혔고, 기본 스크린샷은 축소 JPEG라 화질이 흐림 → 소개서 작업에서는 화면을 좌우·상하로 나눠 원본 해상도로 찍고 이어 붙여 해결.
- PowerPoint에서 파일이 열려 있으면 덮어쓰기가 안 돼 버전이 의도치 않게 늘어남.
- 버튼 일부는 실제로 눌러보지 않고 설명 → 내용 검토 필요 항목으로 따로 보고하게 함.
- 소개서의 "새로 바뀐 점" 슬라이드에 Claude의 추정이 섞였음 → 구버전 화면을 직접 열어 비교한 사실로 다시 씀. "확인한 사실만 쓰라"는 지시가 필요했다.
- 스킬을 새 대화에서 실제로 불러 끝까지 돌려보는 검증(관리자용 시험)은 중간에 멈춤.
