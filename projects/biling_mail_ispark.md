# 사업 변경 요청 메일 작성기 (로컬 웹앱)

> 스킬 문서(SKILL.md)의 메일 양식 규칙을 그대로 코드로 옮겨, 폼 입력 → 실시간 미리보기 → 회사 메일(SMTP)로 바로 발송까지 되는 개인용 웹 화면

| 항목 | 내용 |
|---|---|
| 기간 | 2026-09-30 (핵심 구현 약 1시간) ~ 2026-10-15 (후속 문의) |
| 세션 수 | 1개 세션 (같은 세션을 이어서 2일 사용) |
| 기술 스택 | Next.js 16 (App Router) + TypeScript, Tailwind CSS 4, nodemailer, libSQL(로컬 SQLite), ExcelJS, Vitest |
| 결과물 형태 | 로컬 웹앱 (127.0.0.1 전용) + 더블클릭 실행용 `start.bat` + PRD 문서 |
| 상태 | 완료 (M1~M4 운영 중) / 외부 배포(M5)는 보류 |

## 목표 / 배경

- 사내 매출/매입 계산서·발주·지급·수금 변경 요청 메일을 정해진 5개 항목 양식으로 반복 작성하고 있었음.
- 매번 양식 맞추기, 금액 천 단위 쉼표, `>` → `→` 치환, 수신자/참조 입력 같은 단순 반복이 많았음.
- 이미 만들어 둔 Claude 스킬(SKILL.md)의 규칙을 **AI 없이 규칙 기반**으로 웹 화면에 옮겨, 작성부터 발송까지 1분 안에 끝내는 것이 목표.
- 처음에는 "배포까지" 생각했지만, 혼자 쓰는 도구라 보안·회사 메일 서버 정책을 고려해 로컬 운영으로 결정.

## 클로드 활용 방식

- **계획서 먼저 + 질문하며 PRD 작성**: 첫 지시에서 "하기 전에 계획서 먼저, 질문하면서 PRD 만들어줘"라고 요청.
  - Claude가 `AskUserQuestion`으로 메일 서비스 종류, 연동 범위(초안 저장/직접 발송/mailto/복사), 입력 방식(폼/AI 정리), 배포 위치 등을 객관식으로 질문 → 답을 반영해 `PRD.md` 작성.
  - PRD에 기능 요구사항(F1~F7), 비기능 요구사항, 마일스톤(M1~M5), 오픈 이슈, 리스크까지 정리됨.
- **"진행" 한 마디로 마일스톤 단위 구현**: M1(본문 생성 로직 + 테스트) → M2(작성 화면) → M3(SMTP 발송·설정) → M4(발송 이력·복제) 순서로 진행.
- **SKILL.md 예시를 테스트 기대값으로 사용**: 본문 생성 로직을 순수 함수로 분리하고 Vitest로 스킬 문서 예시와 글자 단위 일치 검증.
- **"너가 테스트해"**: Claude가 직접 검증.
  - Claude Browser(preview) 도구로 화면 클릭 테스트(자동완성, 임시저장 복원, 확인 모달, 이력 복제).
  - 가짜 SMTP 서버를 띄워 발송 전체 흐름 검증 → 실제 메일 서버는 로그인 테스트 → 본인 주소로 1통 테스트 발송(사용자 승인 후).
  - 메일 서버의 포트 개방 여부와 TLS 인증서 만료일까지 미리 확인해 PRD 리스크에 기록.
- **비밀값은 채팅 대신 파일로**: SMTP 비밀번호는 Claude가 메모장으로 `.env.local`을 열어 주고 사용자가 직접 입력. Claude는 수정 시각으로 저장 여부만 확인.
- **사내 시스템 연동 탐색 (Claude in Chrome)**: "사업번호 가져오는 것도 연결되나?" 요청에 사용자 Chrome에서 사내 사업관리 시스템을 열고(로그인은 사용자가 직접), 조회 전용으로 화면 구조를 분석. 연결 방식 3가지(엑셀 업로드/북마클릿/자동 조회)를 장단점 표로 제안 → 엑셀 업로드 방식 채택.
- **메모리 활용**: "로컬 전용 운영, 배포 보류, 재개 시 M5부터"를 프로젝트 메모리에 저장해 다음 대화에서 이어갈 수 있게 함.

## 결과물

**주요 기능**
- 항목별 입력 폼: 사업번호/사업명(여러 건), 대상 구분(매출·매입계산서/발주/지급/수금), 사유, 변경 내용(일정/금액/기타), 승인자·승인 일시·승인 방식
- 본문 자동 생성: 제목 자동 생성, 금액 쉼표+"원", `>`→`→`, 공통/사업번호별 변경 묶음, 빈칸은 `OOO`로 표시(지어내지 않음)
- 실시간 미리보기 + 빈칸 개수 배지 + 제목/본문 복사 버튼(발송 실패 시 대체 수단)
- SMTP 직접 발송: 발송 전 확인 모달, 내 주소 자동 참조, 오류 메시지 한글 안내
- 기본 수신자/참조 저장, 설정 화면의 SMTP 연결 테스트
- 발송 이력 저장·검색, "복제해서 작성"
- 작성 중 자동 임시저장(localStorage) 및 복원
- 사내 사업관리 시스템 엑셀 업로드 → 사업번호 입력 시 사업명 자동완성, 계산서/수금 일정을 "변경 전" 값으로 불러오기(파일 종류는 헤더로 자동 판별)
- `start.bat`: 이미 실행 중이면 브라우저만 열고, 첫 실행 시 자동 빌드

**구조**
```

app/settings/page.tsx      수신자 기본값, SMTP 테스트, 엑셀 업로드

components/Composer.tsx    폼 + 미리보기 + 발송 모달
```

## 잘된 점

- 계획서(PRD) → 마일스톤 순서로 진행해서, 약 1시간 만에 실사용 가능한 버전까지 도달.
- 스킬 문서의 예시를 그대로 테스트로 고정해 "양식이 미묘하게 틀리는" 문제를 원천 차단.
- 발송 실패 대비책(복사 버튼)을 처음부터 설계에 포함, 실수 발송 방지용 확인 모달도 기본 탑재.
- 비밀번호를 채팅에 쓰지 않고 로컬 파일로만 관리, 서버도 127.0.0.1에만 바인딩.
- 저장소를 추상화해 두어 나중에 배포(Vercel + Turso)로 옮길 길은 열어 둠.

## 아쉬운 점 / 시행착오

- **한글 .bat 파일 실패**: 파일명·내용에 한글이 들어간 `실행.bat`이 cmd에서 깨져 더블클릭이 안 됨 → ASCII + CRLF의 `start.bat`으로 교체.
- **포트 충돌**: 3000번을 다른 프로그램이 사용 중이어서 3100번으로 변경. 테스트용으로 켜 둔 서버와 포트가 겹친 것도 원인.
- **비밀번호 입력 안내 반복**: "어디에 넣으라고?" → 메모장을 직접 열어 주고 몇 번째 줄인지까지 안내해야 했음. 비개발자 사용자를 위한 안내는 처음부터 구체적으로.
- **http 사이트 다운로드 차단**: 사내 시스템이 http라 Chrome이 엑셀 다운로드를 "안전하지 않은 파일"로 멈춤 → 사용자가 직접 [유지]를 눌러야 했고, 3개 중 일부 파일은 그날 처리되지 못함.
- **PowerShell 출력·문법 문제**: 테스트 응답이 출력되지 않거나 정리 명령이 문법 오류로 막혀 Node 스크립트로 재실행.
- 외부 배포(M5)는 회사 메일 서버의 해외 IP 차단 가능성, 비밀번호 유출 우려로 보류 상태.
- 메일 서버 TLS 인증서 만료 예정일이 있어, 이후 발송 오류 시 1순위 점검 대상으로 메모해 둠.

## 다음에 재사용할 프롬프트·팁

```
현재 폴더에 있는 MD 파일(양식 규칙)을 읽어서 바로 작성할 수 있는 웹 화면을 하나 만들어보자.
나만 쓸 거고, 편의를 위해 내 이메일과 연결하면 좋겠어.
하기 전에 계획서부터 세우고, 질문(ASK YOUR QUESTION)하면서 PRD를 만들어줘.
```

```
너가 테스트해. 화면 클릭 테스트하고, 실제 발송 전에는 가짜 메일 서버로 먼저 검증한 다음
진짜 서버는 로그인만 확인해. 실제 발송은 나한테 물어보고 내 주소로 한 통만.
```

```
이 사내 시스템에서 [번호/이름] 데이터를 가져오는 것도 연결할 수 있나?
크롬으로 열어봐, 로그인은 내가 할게. 조회만 하고 연결 방법 몇 가지를 장단점 표로 제안해줘.
```

- 팁: 양식 규칙이 있는 스킬/문서가 있으면 "예시를 테스트 기대값으로 써 달라"고 하면 결과 일치가 보장된다.
- 팁: 비밀번호·토큰은 채팅에 적지 말고 `.env.local`에 직접 넣는다. Windows 배치 파일은 ASCII로.
