# 사내 업무시스템(IBMS2) MCP 연동 · 업무활동 자동 기록 · 계약승인 전자결재 작성 스킬

> Claude Code에 사내 업무시스템(IBMS2) MCP 서버를 붙여 업무활동 기록·주간보고·월간 AI 사용현황 등록을 자동화하고, IBMS2 계약 정보를 그룹웨어(아마란스) 「계약 승인 신청서」로 옮겨 적는 반복 업무를 누구나 쓸 수 있는 스킬로 만든 프로젝트

| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-07 ~ 2026-11-15 (약 6주) |
| 세션 수 | 13개 (대화형 4개 + 예약 작업 자동 실행 9개) |
| 기술 스택/도구 | Claude Code, 사내 IBMS2 MCP 서버(HTTP transport), Scheduled Tasks, Claude in Chrome(브라우저 자동화), Node.js(대화 기록 파싱), Agent Skill(SKILL.md + references + scripts) |
| 결과물 형태 | MCP 서버 등록(user scope), 예약 작업 2종(SKILL.md 프롬프트), 월간 사용현황 수정본(md), 공유용 스킬 패키지(`.skill`/zip) |
| 상태 | 운영 중 — 예약 작업은 평일·매주 자동 실행, 스킬은 팀 공유 단계 |

## 목표 / 배경
- 회사가 Claude Team 요금제를 도입하면서 "Claude로 일한 날은 IBMS2에 업무활동을 남기고, 매월 AI 사용현황(투입시간·기준시간·절감시간)을 등록"하는 규정이 생겼다. 11월부터는 일일 업무활동·주간 업무보고도 의무화.
- 매일 손으로 "오늘 Claude로 뭘 했고 몇 시간 걸렸는지"를 정리하는 건 그 자체가 부담이라, **Claude가 자기 작업 기록을 읽고 직접 등록**하게 만드는 것이 목표.
- 별도로, 영업대표가 계약승인 절차를 밟을 때 IBMS2 「계약 및 원가」 화면 내용을 그룹웨어 전자결재 「계약 승인 신청서」에 그대로 옮겨 적는 반복 업무가 있었다. 이를 자동화하고, 다른 사람도 같은 방식으로 쓸 수 있게 스킬로 패키징하고자 했다.

## 클로드 활용 방식
- **MCP 연동**
  - `claude mcp add --transport http -s user ...` 명령으로 사내 IBMS2 MCP 서버를 user 범위로 등록 (CLI가 없으면 `~/.claude.json`의 `mcpServers`에 직접 기입하도록 지시).
  - 업무활동 조회/등록(`work_list_my_activities`, `work_log_activities`), 확정(`work_confirm_activities`), 주간보고 생성·저장(`work_generate_report`, `work_save_report_summary`) 등 MCP 도구를 사용. 업무활동 코드값(활동유형·업무구분·AI도구 등)도 먼저 Claude에게 물어 파악.
- **월간 사용현황 등록 (대화형)**
  - 사내 가이드 PDF를 첨부하고 "묻지 말고 끝까지 알아서" 형태의 긴 지시문을 붙여넣어, 지난달 대화 기록·작업 파일·커밋 이력을 뒤져 누락된 업무활동을 먼저 등록하고 월간 건을 작성·확정.
  - 추정값에는 반드시 "(추정)"과 근거를 붙이고, 절감률 상한(70%)을 지키게 함.
- **예약 작업 (Scheduled Tasks)** — 대화 중 "평일 저녁 일일 업무활동, 금요일 오전 주간 업무보고를 자동 등록되게 설정해줘"로 생성.
  - 작업 정의는 `~/.claude/scheduled-tasks/<name>/SKILL.md`에 자연어 절차서로 저장되고, 실행 시 `<scheduled-task name=...>` 세션으로 자율 실행된다.
  - 사용자가 없는 상태로 돌기 때문에 "초안까지만, 확정·제출 금지", "비밀번호·키는 옮기지 말고 변경 권장만" 같은 **하지 말 것** 섹션을 명시.
- **대화 기록 파싱**: PC에 Python이 없어 Node로 `~/.claude/projects/**/*.jsonl`을 읽고, UTC→KST 변환, 메시지 간격 15분 미만 구간 합으로 실작업 시간을 산출.
- **브라우저 자동화 (Claude in Chrome)**
  - 사용자 크롬의 로그인 세션을 그대로 활용. claude.ai 웹 채팅 이력은 페이지 내 `fetch`로 대화 API를 읽어 Code 외 작업도 수집(읽기 전용).
  - 그룹웨어 전자결재 양식은 팝업으로 열려 탭 그룹 밖에서 조작이 안 됐다 → `window.open`을 후킹해 URL을 잡아 같은 탭에서 여는 우회책을 찾음.
  - 양식 본문(iframe 안 에디터 표)은 `javascript_tool`로 스크립트를 실행해 일괄 입력.
- **스킬 제작**: 한 건을 실제로 끝까지 처리한 뒤 "이거 스킬로 만들어줘 아무나 쓸수있게"로 스킬화, `.skill`(zip) 파일로 패키징해 공유 방법까지 안내받음.

## 결과물
**1) 예약 작업 2종**

| 이름 | 주기 | 역할 |
|---|---|---|
| `ibms2-daily-activity` | 평일 18:00 | 오늘(KST) Claude Code 세션 + claude.ai 채팅을 모아 작업 단위로 묶고, 투입/기준/절감 시간을 추정해 IBMS2 업무활동 **초안** 등록. `clientRefKey`로 중복 방지, 이미 등록된 건 건너뜀 |
| `ibms2-weekly-report` | 금요일 09:30 | 이번 주 빠진 활동을 먼저 보충 등록한 뒤, 주간 업무보고를 생성해 대분류(●)·과제(ᄋ)·상세(-) 형식 본문과 headline, 차주 계획을 작성해 **초안 저장** |

- 실행 결과는 표(ID·제목·출처·업무구분·실제→기준 시간·절감·산출물)와 추정 근거로 보고하고, "Office 연동 작업은 기록에 안 남으니 알려 달라"는 질문으로 마무리.

**2) 스킬 `ibms2-contract-approval-draft`**
```
ibms2-contract-approval-draft/
├── SKILL.md                  # 트리거 문구, 범위(보관=임시저장까지), 7단계 절차
├── references/field-guide.md # 양식 항목별 작성 기준 (금액 단위 변환, 사업영역 판단 기준 등)
└── scripts/fill_form.js      # DATA 객체만 바꿔 실행하는 양식 자동 입력 스크립트
```
- 절차: 대상 확인 → 두 사이트 열고 사용자 로그인 요청 → IBMS2 계약 화면 읽기(입력칸 값은 스크린샷으로) → 전자결재 양식 열기(팝업 후킹) → 스크립트로 작성 → **보관 후 재열람 검증** → 판단 항목·사용자 할 일 보고.
- 사람마다 다른 값(기안자, 결재선, 부서)은 양식 자동값을 그대로 두어 누가 써도 동작하도록 설계.

**3) 월간 사용현황**: 가이드 기준에 맞춘 월간 건 수정본(md) 작성 및 재확정.

## 잘된 점
- **"초안까지만" 원칙**: 예약 작업과 스킬 모두 확정·상신 같은 되돌리기 어려운 동작을 사람에게 남겨, 자동화하면서도 통제권을 유지했다.
- 예약 작업 지시문이 입력 출처, 코드값, 시간 산정 방식, 중복 방지 키, 금지 사항, 결과 형식까지 담은 **완결된 절차서**라 무인 실행에서도 결과가 안정적이었다.
- 전자결재 팝업, iframe 에디터, 보관 후 값 유실(HTML 속성까지 세팅해야 유지) 같은 함정을 한 번 실전에서 겪고 그 해결책을 스킬에 그대로 녹였다.
- 사업영역·원가테스트처럼 판단이 필요한 항목은 "판단 근거를 보고에 남겨라"로 정해 검토가 쉬워졌다.
- Code 세션뿐 아니라 웹 채팅까지 수집 범위를 넓혀 실제 업무량에 가까운 기록이 됐다.

## 아쉬운 점 / 시행착오
- **확정을 너무 빨리 했다**: 월간 건을 확정한 뒤 수정할 곳을 발견했는데 MCP·화면 모두 확정 건은 수정 불가 → 관리자에게 확정 해제를 요청해야 했다. 이후 "확정은 사람이 검토 후"로 원칙을 바꿨다.
- **수집 범위 누락**: 처음엔 데스크톱 앱 세션만 보고 터미널·VS Code 세션을 빠뜨려 활동이 누락됐다. 대화 기록은 실행 환경과 무관하게 `~/.claude/projects/`에 모인다는 것을 알고 나서 보완.
- 대화 중에 그룹웨어 로그인 정보와 MCP 토큰을 그대로 붙여넣었다. Claude는 비밀번호 입력을 거부했지만 기록에는 남으므로, 이후 예약 작업에 "키 발견 시 변경 권장" 알림을 넣었다. 처음부터 토큰은 환경변수/설정 파일로 넘겼어야 했다.
- 예약 작업이 Chrome 확장이 꺼져 있으면 채팅 수집을 건너뛰어, 그날 웹 채팅 작업은 누락될 수 있다.
- MCP 계약 조회 도구는 사용자 권한 그룹에 따라 거부될 수 있어, 결국 화면 읽기(스크린샷) 방식이 기본 경로가 됐다.
- 도구 출력에 URL 형태 문자열(`?`, `=`, `&`)이 섞이면 출력이 차단되는 제약 때문에 스크립트 반환값을 가공해야 했다.
- 스킬 안에 접속 주소와 실제 건의 예시 데이터가 들어가 있어, 사내 공유는 괜찮지만 외부 공유 전에는 정리가 필요하다.

## 다음에 재사용할 프롬프트·팁

MCP 서버 등록 (CLI 실패 시 대안까지 한 번에):
```
아래 명령으로 <서버명> MCP 서버를 user 범위로 등록해줘.
claude 명령이 없으면 ~/.claude.json 의 mcpServers 에 같은 내용으로 직접 넣어줘.
claude mcp add --transport http -s user <서버명> <URL> --header "Authorization: Bearer $TOKEN"
```

무인 실행 예약 작업 (절차 + 금지사항 + 결과 형식):
```
평일 18시에 오늘 내가 Claude로 한 작업을 <업무시스템> 업무활동 초안으로 등록하는 예약 작업을 만들어줘.
- 출처: ~/.claude/projects/*.jsonl (UTC→KST), 브라우저가 연결돼 있으면 웹 채팅 기록도 읽기 전용으로
- 실작업 시간 = 메시지 간격 15분 미만 구간 합, 추정값엔 "(추정)"과 근거
- 중복 방지 키: <PREFIX>:YYYY-MM-DD:<슬러그>
- 하지 말 것: 확정·제출, 비밀번호/키 옮기기, 오류 시 우회 시도
- 결과: 등록 건 표 + 추정 근거 + "직접 확인 후 확정하세요"
```

한 건 직접 처리 → 스킬화 (반복 업무 자동화 패턴):
```
<시스템A>에서 내용을 보고 <시스템B> 양식에 맞춰 작성하는 일을 할 거야.
매번 대상 리스트를 줄 테니, 작업 범위는 임시저장(보관)까지만. 상신/제출은 내가 한다.
양식 내용은 네가 판단하되, 판단이 들어간 항목은 근거와 함께 따로 보고해.
(한 건 끝난 뒤) 이거 스킬로 만들어줘. 아무나 쓸 수 있게, 사람마다 다른 값은 하드코딩하지 말고.
```

팁: 되돌릴 수 없는 동작(확정·상신·제출)은 프롬프트에 "하지 말 것"으로 명시하고, 저장 후에는 "다시 열어서 제대로 저장됐는지 확인해줘"로 검증 단계를 꼭 넣는다.
