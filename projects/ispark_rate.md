# 입찰 계량평가 예상점수 산출 도구

> 공공 SW 유지보수 입찰(협상에 의한 계약)의 정량평가·가격평가 점수를 제안요청서(HWPX)와 회사 데이터로 미리 계산하는 사내 웹앱

| 항목 | 내용 |
|---|---|
| 기간 | 2026-10-13 ~ 2026-11-12 (집중 개발은 10-13 하루, 11월에 차등점수제 보완) |
| 세션 수 | 1 (장기 세션 하나로 이어서 진행, 사용자 메시지 약 27개) |
| 기술 스택 | Next.js 16 + React 19 + TypeScript, Tailwind CSS 4, Node 내장 SQLite, JSZip(HWPX/XLSX 파싱), Vitest |
| 결과물 형태 | 로컬 사내 웹앱(localhost) + 산식 엔진 라이브러리 + PRD 문서 |
| 상태 | 진행중 (M1·M2 완료, M3 저장 완료 / 배포·인사 시스템 연동·자가진단표 출력은 남음) |

## 목표 / 배경
- 공공 SW 유지보수 입찰은 기술평가 90점(정량+정성) + 가격평가 10점 구조. 정량·가격은 산식이 공개돼 있어 제출 전에 계산이 가능하지만, 발주기관마다 기준이 달라 수기 계산 오차가 잦았다.
- 같은 종류의 사업인데도 지자체형과 중앙부처형의 정량 배점, 신용등급 점수표, 가격 산식(최저가 하한 80% vs 70%)이 서로 달랐다.
- 일부 항목(참여인력, 실적건수, 가격)은 **상대평가**라 경쟁사에 따라 점수가 바뀌는데, 이를 감으로 판단하고 있었다.
- 목표: "가능한 한 정확한 점수". 확정 점수와 추정 점수를 분리하고, 항목마다 산출 근거(원문 인용·산식·입력값)를 보여주는 것.

## 클로드 활용 방식
- **PRD 먼저**: 첫 지시가 "우선 PRD 먼저 잡아보고 만들어보자, 진행하면서 나랑 얘기해". PRD를 v0.2 → v0.5까지 고치며 '확정된 결정' 표에 날짜와 함께 결정을 쌓았다.
- **질문하며 진행**: AskUserQuestion으로 평가 범위, 주력 입찰 유형, VAT 포함 여부, 공동수급 지분율 입력 방식, 기술 스택, 서류 관리 범위 등을 선택지로 물었다.
- **기준은 추정하지 말고 문서로**: 사용자가 "기준에 대해서는 문서 요청해줘"라고 해서 Claude가 필요한 평가기준 원문 체크리스트를 만들어 요청했다. 실제 RFP 샘플 2건과 실적 엑셀을 직접 첨부.
- **웹 검색으로 규정 원문 확보**: RFP에 "조달청 규정에 따름"만 있던 가격 산식은 WebSearch/WebFetch로 국가법령정보센터의 계약예규 별표 원문을 찾아 HWPX 수식까지 열어 확정했다.
- **마일스톤 단위 구현 + 커밋**: M1(산식 엔진+경계값 테스트) → 커밋 → M2(추출·업로드·화면) → 저장 기능 → 보완. "커밋하고 두번째 단계해" 식으로 단계 진행.
- **Browser pane(Claude Preview)**: 개발 서버를 띄우고 탭 생성·JS 실행·콘솔/서버 로그 확인으로 화면을 검증. "이슈 떠있는거 확인해봐" 한마디로 Next.js 오류 오버레이를 찾아 고쳤다.
- **메모리 활용**: 프로젝트 원칙("단계마다 상의, 기준 문서 요청")과 브라우저 테스트 예절을 memory에 남겨 다음 대화에도 유지.
- **실측값 디버깅**: 11월에 "저장된 건에서 0.25점 차이 나면 어디가 문제일까?"를 물었고, 항목별 점수 단위를 표로 분석 → 사용자가 "차등점수제야"라고 짚자 바로 기능으로 반영.

## 결과물
**기능**
- RFP(HWPX) 평가기준 규칙 기반 추출: 사업비, 발주기관 유형 판별, 배점, 유사사업 범위, 가격 산식, 차등점수제 여부를 원문 인용과 함께 표시하고 템플릿과 다른 점 표시
- 발주기관 유형별 템플릿(지자체형 T1 / 국가기관형 T2) + 공고 내용으로 덮어쓰기
- 정량 항목 계산기: 참여인력(ITSQF 직무·경력 년+개월·참여율), 실적금액(규모비율), 실적건수(업체수별 등급 배분), 신용등급, 안전보건, 가격점수
- 결과를 **확정 / 확인 필요(최소~최대) / 상대평가(시나리오)** 로 구분, 협상적격(85%)에 필요한 정성 최소점수 역산
- 실적 엑셀 업로드 → 최근 3년·하수급 필터, 건별 인정/애매/제외 판정 기억, VAT ÷1.1 처리
- 상대평가 what-if 표("경쟁사 최고 원점수가 X면 우리는 Y점"), 차등점수제 순위 시뮬레이션
- 입찰 건 저장·다시 열기, 회사 공통 데이터 자동 저장, 개찰 후 실제 점수 입력 칸(예측 적중률 축적용)
- 서류 체크리스트(RFP 제출서류·참가자격 서류·정량 증빙 자동 생성) + 회사 공통 서류 유효기간/만료 경고 페이지
- 실적 엑셀 명령줄 가져오기(`npm run import-records`)

**구조**
```
docs/PRD.md              요구사항·확정 결정·열린 질문·마일스톤
src/engine/              순수 함수 산식 엔진 (templates.ts, evaluate.ts, ranking.ts, round.ts, items/*)
src/engine/__tests__/    단위 테스트 (최종 104개)
src/lib/                 hwpx.ts, xlsx.ts, zipxml.ts(파서), rfpExtract.ts, performanceImport.ts, documents.ts
src/server/              db.ts, repo.ts (SQLite 저장소, 배포 시 Postgres 이전 고려해 한 곳에 모음)
src/app/                 평가 화면, /bids(저장된 입찰), /documents(회사 서류), api/*
src/components/          RfpPanel, RecordsPanel, CompanyPanel, PricePanel, ResultPanel, RankingPanel, ChecklistPanel 등
scripts/import-records.ts
```

## 잘된 점
- **"계산은 코드, LLM은 추출만"** 원칙을 PRD에 박아두어 점수가 결정적으로 재현된다.
- 경계값 테스트가 실제 버그를 잡았다: VAT 포함 금액 ÷1.1의 부동소수점 오차로 규모비율 100%가 99.99%가 되어 5점이 4.5점으로 떨어지던 문제 → 정수 연산(×10÷11)으로 해결.
- 규정 원문 확인으로 지자체(최저가 하한 80%)와 국가기관(70%) 가격 산식 차이를 발견해 엔진에 반영.
- 사용자가 직접 실무 지식을 던지면(IT시스템 기술지원 직무, 차등점수제) 즉시 테스트와 함께 반영되는 짧은 루프가 잘 돌았다.
- 보안/개인정보 검토를 먼저 해서 "인력은 이름·경력연수만 저장, 로그인 필수" 같은 배포 조건을 PRD에 확정.

## 아쉬운 점 / 시행착오
- **사용자 작업 탭을 테스트 중 새로고침해 입력값이 날아감**. 당시엔 저장 기능이 없어 인력·신용등급 등은 재입력해야 했다. 이후 "테스트는 새 탭에서만, 사용자 탭은 읽기만" 규칙을 메모리에 남김.
- 개발 서버가 떠 있는 동안 컴포넌트를 여러 번 나눠 수정해 중간 상태 오류(`... is not defined`)가 화면에 노출됨 → 한 번에 쓰기로 개선.
- 브라우저에서 `new Date()`로 기본 날짜를 만들어 Next.js 경고 발생 → 서버에서 요청 시점(한국 시간)으로 계산하도록 수정.
- 처음엔 Python/Streamlit을 추천했다가 Vercel 배포 조건이 나오자 Next.js 단일 스택으로 변경.
- 차등점수제는 RFP에 적혀 있었는데 초기 추출 대상에서 빠졌다. 실측 차이가 나서야 반영됨.
- 배포(Vercel), 인사 시스템 연동, 자가진단표 자동 출력(M4)은 아직 미완.
